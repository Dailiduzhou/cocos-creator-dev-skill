## Design

`SKILL.md` establishes the version/platform contract, routes to topic references, and defines implementation and validation expectations. It is not a duplicate API encyclopedia. References stay short and link to versioned official sources. Existing skill name `cocos-creator-dev` is preserved.

Examples use the Creator 3.8 documentation baseline. Earlier 3.x versions, advanced subsystems, and platform-specific behaviors require fresh version checks. Documentation audit and static evaluation are not claims of editor/device validation.

## Maintenance workflow

1. Snapshot the old skill before editing.
2. Verify the affected topics against official versioned documentation and project declarations.
3. Update the smallest relevant references and keep the main workflow lean.
4. Run paired evaluations using separate contexts and output directories; record evidence and actual available timing metrics.
5. Aggregate results with skill-creator and generate its review HTML for human feedback.
6. Revise based on feedback, preserving prior iteration results.
7. Update the prebuilt archive separately when preparing a release.

The workspace is intentionally excluded from releases and Git because it contains generated outputs and local run metadata. Reusable regression prompts remain with the skill source.
